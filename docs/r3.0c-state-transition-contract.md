# R3.0C — Viewmodel State-Transition Contract (CP1 round-2 retrofit, F11)

Status: **DECLARED, DISABLED** (governance/r3.0c/capabilities.json
`viewmodel_state_transition_contract.enabled = false`). No viewmodel exists at C5R;
this document is the gate that C7_UI must satisfy before it ships.

## Why this contract exists

CP1 round-2 BLOCK adjudication F11: without a state-transition contract, the viewmodel could
overlay a stale result while a new one is being computed. The user reads the old number as the
new lap's outcome. The honesty contract — `framing pass-through, viewmodel never re-words` —
silently fails because the underlying result lifecycle was never specified.

## The rule

The viewmodel MUST clear the prior comparison result AND render a "computing" / "blocked" /
"unavailable" placeholder on EVERY transition listed below. The placeholder MUST be visually
distinguishable from a real result.

### Transitions that force a clear

1. Reference lap selection changes (any field: sessionId, lapId, selection method).
2. Comparison lap selection changes.
3. Case association changes (trackId, layoutId, positionBasis, positionDirection).
4. Channel mapping changes (any channel R3.0C depends on: lap, track_position, speed,
   lateral_accel, steering, brake, throttle).
5. Case reopen (the cased was closed and is opened again).
6. The orchestrator returns `eligible=false` for a previously-eligible (reference, comparison)
   pair — even if the user did not touch UI inputs.
7. A user-confirmed authority (track identity, channel calibration) is revoked.

### The request token

The orchestrator MUST attach an opaque request token to every comparison request. The viewmodel
MUST commit a result ONLY when the token matches the latest token issued. Stale-token results
are DROPPED — never rendered, never queued for "later", never logged as a hidden side effect.

### Blocked state

When the orchestrator returns a blocked result, the viewmodel MUST replace any prior result
with the new blocked-state render — never overlay, never fade-through.

## What this contract does NOT specify

- The exact visual treatment of the placeholder. The UI designer picks the styling; the contract
  only requires distinguishability.
- The token format. Any opaque value that supports identity equality is acceptable.
- Whether the viewmodel uses Alpine reactive properties, a redux store, or a hand-rolled
  observer pattern. The contract is observable behaviour, not implementation.

## Tests C7_UI must add when the capability is enabled

- Switching reference mid-computation: the older result is discarded; only the newer commits.
- Switching comparison mid-computation: same as above.
- Channel-mapping change clears a previously-eligible comparison.
- Blocked result fully replaces the previous eligible result.
- Self-vs-self transition (reference and comparison set to the same lap) clears any prior
  cross-lap result before rendering identical-lap state.
- Adversarial: simulate a stale-token result arriving AFTER a newer-token result; assert the
  stale one is dropped.

## Governance hook

This contract is gated by `governance/r3.0c/capabilities.json`
`viewmodel_state_transition_contract.enabled`. The capability defaults to `false`. A separate
governance test (added at C7_UI ship time) MUST assert that no viewmodel module is loaded
while this capability is disabled.
