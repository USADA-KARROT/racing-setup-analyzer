# R3.0C — Framing-Source Structured Contract (CP1 round-2 retrofit, F12)

Status: **DECLARED, DISABLED** (governance/r3.0c/capabilities.json
`framing_source_structured_contract.enabled = false`). No orchestrator exists at C5R;
this document is the gate that C7_UI / C7 orchestrator must satisfy before it ships.

## Why this contract exists

CP1 round-2 BLOCK adjudication F12: architecture v3 §(6) gave framing-key ownership to the
orchestrator and ordered the viewmodel to render unmodified. But ownership without a SHAPE
rule lets the orchestrator author free-form prose. "viewmodel never re-words" then has no
content rule to enforce: free-form prose IS the wording. The honesty layer leaks at the source.

## The rule

Every framing entry the orchestrator emits MUST be a plain object with exactly this own-key
set (`contracts/r3.0c/comparison-eligibility-contract.js` exposes the same shape under
`FRAMING_KEY_SHAPE`):

- `reasonCode`: must be a member of `contracts/r3.0c/reason-codes.js` REASON_CODES.
- `i18nKey`: must be a member of a frozen FRAMING_I18N_KEY_REGISTRY (declared at C7 ship time).
- `params`: optional plain object whose own values are finite numbers, booleans, null, or
  strings ≤ 256 UTF-8 bytes. No nested arrays. No exotic objects. No prose.

The renderer maps `i18nKey` to a fixed wording in the frozen wording table — same pattern as
the existing reason-code → explanationKey mapping. The orchestrator never authors UI prose.

## What is forbidden in `framing`

- Free-form English / Chinese / Japanese sentences.
- Causal claims (`"driver was late on brakes"`, `"setup is understeery"`).
- Lap-time predictions (`"you would have gone 0.4s faster if..."`).
- Theoretical-best (DEFERRED per architecture v3 §honesty).
- Embedded raw telemetry (numbers identifying a sample index without semantic).
- Driver blame.

## Population rules per framing key

| Field | Allowed populated only when | Renderer treatment |
|-------|------------------------------|---------------------|
| `observed_delta` | At least one delta in `result.metrics` is `available:true` | renders the i18nKey + delta value |
| `likely_driver_behaviour_difference` | A confirmed driver-input channel (brake, throttle, steering) shows a positionally-aligned difference | renders the i18nKey + driver-channel name + magnitude bin (none/small/medium/large) |
| `possible_vehicle_response_difference` | A vehicle-response channel (lat_accel, yaw, speed at corner exit) shows positionally-aligned difference NOT explainable by aligned driver input | renders the i18nKey + channel name + magnitude bin |
| `cannot_distinguish_reasons` | Always emitted (even empty) | array of `{reasonCode, i18nKey, params}` |

When the orchestrator cannot populate a field per these rules, it MUST set the field to
`{reasonCode: 'CANNOT_DISTINGUISH', i18nKey: 'r3_0c.framing.cannot_distinguish', params: null}`
— NOT a free-form explanation, NOT a fallback string. The `CANNOT_DISTINGUISH` reason code
is a registered member of `contracts/r3.0c/reason-codes.js` REASON_CODES (added explicitly
so this fallback is internally satisfiable — formal Codex round-2 F12 closure).

## Tests C7 must add when the capability is enabled

- The orchestrator's framing fields are STRUCTURAL: assert each conforms to
  `FRAMING_KEY_SHAPE` AND each `reasonCode` is a member of `REASON_CODES` AND each `i18nKey`
  is a member of `FRAMING_I18N_KEY_REGISTRY`.
- Adversarial: a test orchestrator that returns `framing.likely_driver_behaviour_difference =
  '你晚煞 0.3 秒'` (a string instead of structured object) MUST be rejected by a structural
  validator before render.
- Adversarial: a test orchestrator that returns `framing.observed_delta.i18nKey = 'NOT_IN_REGISTRY'`
  MUST be rejected.
- Adversarial: a test viewmodel that wraps a structured framing entry with extra prose around
  the rendered i18nKey output fails an "no extra text near framing label" UI test.
