# R2.5 — Setup A/B & Quantitative Recommendation (contracts + honesty)

Turns the deferred `quantitativeSetupRecommendationEligible` (forced false — "no validated click→rate
mapping") into an HONEST quantitative layer on the SAME `runAnalysisWorkspace` / `runAnalysisCase` path. The
frozen dynamics-model, presets, and yaw engine are untouched — A/B and the sensitivity are pure orchestration
over the model.

```
setup-ab.compareSetups(caseA, caseB, opts)                       → model-grounded predicted deltas (Model)
quantitative-setup-recommendation.recommendSetupChange({...})    → physical-unit change to hit a target (Model)
analysis-workspace (opts.quantitative) / viewmodel / index.html  → capability flags + Quantitative section
```

## Setup A/B
`compareSetups(caseA, caseB, opts)` (exposed in the UI as the F4 · Setup A/B what-if panel) runs the model on two AnalysisCases (same injected runner) and reports the
predicted deltas of understeer gradient, roll-stiffness distribution, total roll stiffness, and wheel rates,
plus a directional summary (`b_more_understeer` / `b_more_oversteer` / `no_meaningful_balance_change`). It is a
model PREDICTION (credibility `Model`), not a measured result and **not a lap-time claim** — a what-if, never
proof a setup is faster. Both runs must be valid model runs, else blocked. A `plausibilityWarnings` list flags
(non-blocking) any known parameter outside its plausible range, so an implausible what-if is not read as a clean result.

## Quantitative recommendation
`recommendSetupChange({ analysisCase, target:{metric, delta}, parameterKey, runner })`:
1. run the baseline; read `target.metric` (∈ understeer_gradient / roll_stiffness_dist_front /
   total_roll_stiffness).
2. perturb ONLY `canonicalInputSnapshot[parameterKey].value` (∈ front/rear ARB, front/rear wheel rate, front
   weight %) on a CLONED case by a relative step, re-run, finite-difference the local sensitivity
   `S = Δmetric/Δparam`.
3. if the parameter barely moves the metric (`|Δmetric| < changeFloor`) → **blocked**
   (`DEGENERATE_SENSITIVITY`) — never a divide-by-near-zero.
4. `recommendedDeltaPhysical = target.delta / S` in PHYSICAL units (Nm/deg, N/mm, %); reject an implausible
   recommended value (e.g. a negative ARB, an out-of-range weight, or a predicted result outside a plausible
   band).
5. re-run the model at the recommended value → `predictedMetricAfter` + `residual` (the linearization error),
   and the `sideEffects` (how EVERY other tracked metric moves, including unchanged = 0, so the trade-off is unambiguous).
6. output carries a concrete `validationStep`, `limitations` (`local_linearization`, `single_parameter`,
   `model_grounded_not_measured`, and `large_extrapolation…` / `linearization_residual…` when relevant), and
   `credibility:'Model'`.

## Honesty boundaries (§10 / §19)
- **No hardware "clicks" (§19-6).** `clicksEligible` is FALSE — there is no validated per-car click→rate
  mapping, so a precise click count is never emitted. Recommendations are in physical units; the engineer
  translates to clicks. The UI says so explicitly.
- **Model-grounded, not measured (§19-1/§19-5).** A/B deltas and the sensitivity are the model's prediction
  (credibility `Model`), never measured and never a lap-time promise.
- **Side-effects + validation on every recommendation (§19-8).** The output reports the other metrics' change
  and a back-to-back on-track check; it is a conservative starting point, not a guarantee.
- **Fail-closed + bounded.** Degenerate sensitivity, a non-model-usable perturbation, or a recommended value
  outside its FINITE plausible range (ARB [0,3000] Nm/deg, wheel rate [20,600] N/mm, front weight [40,70] %;
  `total_roll_stiffness` capped at 20000 Nm/deg) → blocked with a reason. No arbitrarily large recommendation.
- **Ballast vs suspension.** `frontWeightPct` is a `weight_distribution_ballast` lever — materially different
  from a spring/ARB change, and the only non-degenerate lever for `understeer_gradient` in the Tier-1 model;
  it is labelled as such in the output, view model, and UI. Pure; never throws; never mutates the input case.
- **Setup context required (§19-2).** Needs a valid, model-runnable AnalysisCase.

## Known limitations (R2.5)
- Recommendations are single-parameter, locally-linear MODEL extrapolations (residual reported); a large
  target needs an iterative re-check.
- Hardware click translation is out of scope (needs a validated per-car click→rate mapping).
- The metric/parameter levers are those the frozen Tier-1 model actually moves; degenerate pairs are blocked.
