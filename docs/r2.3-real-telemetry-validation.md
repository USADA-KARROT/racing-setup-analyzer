# R2.3 — Real Telemetry Validation (contracts + dataflow)

Lets imported telemetry travel the SAME production pipeline as the demo (R2.2): import → map → calibrate
→ window → build an AnalysisCase → run → Model-vs-Actual + Race Engineer + Driver Coach → save/export.
The new abstraction is a **Canonical Telemetry Session** that carries the evidence; observation re-derives
every gate from that evidence (it never trusts a caller-supplied flag).

```
importTelemetry(source) → imported
buildChannelMapping(rawChannels, assignments) → mapping (+ immutable mappingEntries)
buildCalibrationSet(userCalibrations) → calibrationSet
buildCanonicalSession(imported, mapping, calibrationSet, windowRequest) → canonical session (evidence)
runAnalysisWorkspace(case, canonicalSession) → execution/observation/comparison/RE/DC/capability   [SAME orchestrator]
buildAnalysisWorkspaceViewModel(...) → 9-section view
exportAnalysisCase(bundle) / parseAnalysisCaseExport(json) → portable, versioned, closed-schema case
```

## Modules (all PURE/UMD)

| Module | Contract |
|---|---|
| `telemetry-import-adapter.js` | `importTelemetry({format:'csv'|'canonical_json', text|object})` → `{ok, sourceMetadata, rawChannels[{rawColumnId,rawName,rawUnit,values,…}], timebase, sampleCount, warnings, parseErrors}`. Parser-only (no handling claim). REJECTS duplicate headers; every channel keeps a stable `rawColumnId` (column index). |
| `channel-mapping.js` | `buildChannelMapping(rawChannels, assignments)` → `{entries, mappingEntries, byCanonical, suggestions, ambiguities}`. User can map ANY raw column → canonical channel (manual, not limited to auto-detect; telemetry-core only SUGGESTS). `mappingEntries` is the immutable per-assignment list used downstream for both-direction uniqueness. |
| `calibration-registry.js` | `makeCalibration / buildCalibrationSet / deriveCalibrationCapability`. Directional observation is calibration-INDEPENDENT. `signedResponseEligible / calibratedMagnitudeEligible / roadWheelMetricsEligible` are re-derived and ALL `false` in R2.3 (deferred to R2.4). |
| `analysis-window.js` | `proposeAnalysisWindows / validateAnalysisWindow / normalizeYawOptions`. Validation FIRST hard-fails a blocked/non-monotonic timebase (`timebase_blocked`), THEN decides qualifying-sample sufficiency by CALLING the yaw engine (shared logic, no drift). `normalizeYawOptions` is shared with observation. Window validity = enough qualifying samples AFTER exclusion (not absence of any excluded sample). |
| `canonical-telemetry-session.js` | `buildCanonicalSession(...)` / `coerceLegacySession({parsed,definitions}, windowRequest)` / `isCanonicalSession`. Evidence session: `mappingEntries` (immutable), `channels` (projection applied), `time`, `calibrationSet`, `windowRequest`, `timebaseStatus`, `advisory` (display only). coerce reproduces R2.2 `{parsed,definitions}` byte-for-byte. |
| `analysis-case-export.js` | `exportAnalysisCase(bundle)` / `parseAnalysisCaseExport(json)` / `caseSummary(case)`. PURE closed validation — every section is PASSED THROUGH the shared recursive closed schema with **no pre-validate transform**: unknown key anywhere REJECTED (not silently omitted), input aliases (`mappingEntries`/`calibrationSet`/`analysisCase`) rejected, blocker `detail` is **string codes only** (numeric/sample-like arrays rejected), arrays bounded + iterated densely (sparse holes → validated null), exotic input (getter/Proxy that throws, cyclic) **fails closed** (never throws). The `case` is caller-summarized to scalars via the exported **`caseSummary()`** helper BEFORE export — a full/un-summarized case object is rejected (the export never extracts from a deep object, so it can never leak a nested field); private path/sample leaves rejected (value-level, still allows units like `N/mm`); versioned + round-trippable (`parse(export(b))` deep-equals). |
| `telemetry-observation.js` (STRENGTHENED) | A canonical session path re-derives EVERY gate from evidence (never from `advisory`): channel eligibility (`userConfirmed===true ∧ valid projection ∧ one-to-one`, from `mappingEntries`), structural validation (equal finite lengths, finite times, ordered window), window re-validation, calibration higher-metric flags. The legacy `{parsed,definitions}` entry is UNCHANGED → all R2.2 tests stay green. |

## Authority rule (no forgeable session)
Observation treats `canonicalSession.advisory.*` as DISPLAY ONLY and re-derives channel eligibility, the
validated window, and the calibration capability from the raw evidence. A forged `advisory` / `valid:true`
changes nothing. This mirrors R2.1D's never-trust-caller recompute.

## Honesty boundaries (§10)
- Unconfirmed channel identity → observation blocked (the session stays inspectable). §14: an imported
  session that is not analysis-eligible still assembles a case and shows what is blocked + why.
- Directional tendency is raw, sign-agnostic; uncalibrated raw steering is NEVER read as road-wheel angle.
- `signedResponseEligible / calibratedMagnitudeEligible / roadWheelMetricsEligible` are all `false` in R2.3.
- No raw samples / private file paths ever enter a case or an export.

## Capability additions (observation output)
`observation.calibrationCapability = { signedResponseEligible:false, calibratedMagnitudeEligible:false,
roadWheelMetricsEligible:false }` — re-derived, enforceable + testable, deferred to R2.4.

## Known limitations (R2.3)
- Real-world case validation against authorized real telemetry is **pending** (the pipeline is validated
  against sanitized synthetic CSV / canonical-JSON fixtures; no private data in the repo).
- Calibrated magnitude, measured K_us, and road-wheel metrics are deferred to R2.4 (blocked here).
- First-version import adapters = generic CSV + canonical-JSON only (no MoTeC/AiM proprietary binary).
- Calibration entries are recorded and capability-layered, but no R2.3 metric consumes a magnitude yet.

## Prohibited claims
Not all telemetry formats; no measured magnitude / road-wheel from imports; synthetic ≠ real; correlation
≠ causation. All unavailable/blocked states are shown with a reason.
