# R2.6 — Track Intelligence & Corner Coaching (contracts + honesty)

Segments a session into laps → corners → entry/mid/exit phases and reports the DRIVER'S raw-steering
behaviour per phase (correction frequency + abruptness) — on the SAME `runAnalysisWorkspace` orchestrator,
fail-closed when the confirmed channels are absent. The frozen yaw engine / model / presets are untouched;
telemetry-observation.js is NOT modified.

```
track-intelligence.deriveTrackIntelligence(session, observation, caseContext, opts)  → corner cards (Heuristic)
analysis-workspace (adds trackIntelligence) / viewmodel (J · Corner Coaching) / index.html / export
```

## Confirmed-channel gate (RE-DERIVED, never trusted)
The observation's `driverInputs.trackPositionAvailable` / `lapSegmentationAvailable` flags are mere mapping
PRESENCE. Track intelligence **independently re-derives** eligibility for `track_position`, `lap`, `steering`,
`speed`, `lateral_accel` from `session.mappingEntries` using the SAME predicate observation uses for required
channels — **exactly one entry ∧ `userConfirmed===true` ∧ valid projection (scale finite≠0, offset finite,
sign∈{-1,1}) ∧ one-to-one** — and gates on that. A mapped-but-unconfirmed `track_position` → blocked
(`NO_TRACK_POSITION`), even though the presence flag is true. (Mirrors the R2.3/R2.4 never-trust-caller rule.)

## Segmentation
- **Laps**: split by the confirmed `lap` channel (integer-rounded value changes).
- **Corners** (within each lap): consecutive runs where `|lateral_accel| ≥ max(2, p60(|lateral_accel|))` AND
  `speed ≥ max(5, p25(speed))`; a run < `MIN_CORNER_SAMPLES` (9) is discarded; no corners → blocked
  (`NO_CORNERS_DETECTED`).
- **Phases**: entry / mid / exit thirds. Per phase, over the RAW steering slice, the reversal count + rate and
  abruptness P95 (same definitions as driver-coach-insight; deadband = 2% of p95 |steer|) → `{ qualitative,
  reversalRatePerS, abruptnessP95, confidence:'low' }`; a phase < `MIN_PHASE_SAMPLES` (3) → `insufficient_samples`.

## Honesty boundaries (§10 / §19)
- **No (confirmed) track position → no corner attribution; no (confirmed) lap → no per-corner/lap-to-lap.**
  Both fail closed with explicit `blockedReasons` + `cannotConclude`; the session stays inspectable.
- **Driver behaviour, NOT a corner characteristic, NOT a setup finding.** A per-corner observation is the
  driver's steering behaviour in that window — never a corner's understeer, a measured magnitude, or a setup
  recommendation (those stay in Race Engineer / the quantitative layer). Credibility is `Heuristic`, never
  `Measured`/`Model`. Limitation `driver_behaviour_not_a_corner_or_setup_finding` is always carried.
- **Short-window honesty.** Per-phase confidence capped at `low`; insufficient phases/corners are dropped/marked.
- **Raw steering only** (`raw_steering_input_not_road_wheel_angle`); never road-wheel / K_us.
- **Synthetic ≠ real.** The session's `dataProvenance` is carried into a `data_provenance_*` limitation; corner
  coaching is never presented as validated-against-real unless provenance says `real`.
- **Same orchestrator; never mutates** the session or case; eligibility re-derived from evidence.

## Known limitations (R2.6)
- Corner segmentation is a `|lateral_accel|` heuristic (data-adaptive); it is not GPS-line-accurate and is
  labelled as such. Sectors / theoretical-best are out of scope (deferred).
- Per-corner observations are driver-behaviour heuristics (confidence ≤ low), never measured car characteristics.
- Real-data validation against authorized real telemetry is pending; repo fixtures are synthetic.
